## What the existing evidence establishes

The 2026-10-02 read-only inventory and bounded public sample found:

- The existing [Quartz Pages target](https://cybersader.github.io/cyberbase/) had **931 sitemap URLs**. This is a sampled inventory count, not content/asset parity or all-page correctness.
- The inspected production workflow pins Cyberbaser `eac9f1f`, older than the local review branch at `2e0bafb`. An upgrade requires separate review. Inspected Pages metadata had no custom domain; ownership and routing of `cybersader.com` remain unverified.
- The current `/README` and Quartz's root `index.md` differ. No root README counterpart was found in the sampled Quartz sitemap. This is neither a proven 404 nor permission to redirect missing paths to the homepage.
- Two Quartz notes matched selected landmarks in pinned GitHub source. Publish's HTTP shell limited comparison; full rendered parity, desktop freshness, and the old URL inventory remain unmeasured. One asset request was blocked and remains unknown, not proven broken.

The source repository is public: site filtering does not hide tracked files or Git history. This inspection diagnosed no new leak and was not a secret-free history audit. Metadata and samples are not human acceptance. [Decision and evidence limits](/cyberbaser/agent-context/zz-log/2026-10-02-quartz-publishing-migration/).

## Integration questions before source cutover

A publishing UI cannot stand in for complete harness integration. These contracts remain unresolved, not designed APIs:

- **Invocation:** how does the host invoke Cyberbaser and return results?
- **Source and snapshot:** what identifies authoritative text/assets and a consistent pinned base?
- **Selection:** how is owner publication intent bound to that snapshot?
- **Authorization:** which permissions enable inspection, proposal, owner editing, application, and publication, and what records owner authorization?
- **Attribution:** how are contributor, applying actor, and resulting change/publication distinguished?
- **Recovery and observability:** how are retries, failures, durable history, and verified outcomes exposed?

Earlier read-only observations established room/note/plugin availability, not integration. Peer-reported gaps include exact-splice/untouched-byte guarantees, pinnable text/blob snapshots, contributor attribution, and selection integration; these are not independently verified. The peer also reports no dedicated embedded Cyberbaser review. A whole-document upsert with `expectedVersion` and immediate grant permissions is neither an exact operation nor owner proposal approval. Do not aim the current disk/Git writer at room-managed content.

The [snapshot and private-preview integration candidate](/cyberbaser/design/snapshot-preview-integration/) proposes the first usable host-driven milestone: consistent source capture, trusted disposable execution, and authenticated private request/result delivery. These contracts are not selected or implemented. Preview acceptance does not authorize source cutover, exact Apply, governance, or public publication.
