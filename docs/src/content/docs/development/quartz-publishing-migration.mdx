## Integration questions before source cutover

A publishing UI cannot stand in for complete harness integration. These contracts remain unresolved, not designed APIs:

- **Invocation:** how does the host invoke Cyberbaser and return results?
- **Source and snapshot:** what identifies authoritative text/assets and a consistent pinned base?
- **Selection:** how is owner publication intent bound to that snapshot?
- **Authorization:** which permissions enable inspection, proposal, owner editing, application, and publication, and what records owner authorization?
- **Attribution:** how are contributor, applying actor, and resulting change/publication distinguished?
- **Recovery and observability:** how are retries, failures, durable history, and verified outcomes exposed?

Earlier read-only observations established room/note/plugin availability, not integration. Peer-reported gaps include exact-splice/untouched-byte guarantees, pinnable text/blob snapshots, contributor attribution, and selection integration; these are not independently verified. The peer also reports no dedicated embedded Cyberbaser review. A whole-document upsert with `expectedVersion` and immediate grant permissions is neither an exact operation nor owner proposal approval. Do not aim the current disk/Git writer at room-managed content.

The [snapshot and private-preview integration candidate](/cyberbaser/design/snapshot-preview-integration/) proposes the first usable host-driven milestone: consistent source capture, trusted disposable execution, and authenticated private request/result delivery. These contracts are not selected or implemented. Preview acceptance does not authorize source cutover, exact Apply, governance, or public publication.

| Vault feature | Current handling | Status |
|---|---|---|

Safe now: fixing broken links and typos in place, removing stale `publish: true`, adding `cb-publish: false` to anything that must stay private, and exporting Excalidraw drawings that published pages embed.

## Must-have: note source controls (owner requirement, 2026-11-17)

The owner requires feature parity with the Publish site's `publish.js` controls: "the various copy buttons, the show raw, all of that needs to be a part of cyberbase still." Cutover is blocked until every note page has them. The renderer now provides them (`NoteActions`, `NoteDates`, `sourceLinks.ts`):

- [x] A link row under the title: **View source**, **Copy Markdown** (puts the note's raw Markdown on the clipboard, not just a link), **Show raw** and **Download vault**. At 750 px and below only View source and Copy Markdown show. The pencil or Edit control stays separate.
- [x] An **Interact with this note** block after the body: Edit note, Raw note, Download vault and Open in web editor (github.dev).
- [x] A metadata line showing only "📅 created" and "📅 updated" from the vault's `date created` / `date modified` frontmatter (Obsidian's "Wednesday, May 15th 2024, 9:13 pm" form is parsed), plus reading time. No other frontmatter is shown.
- [x] Links point at `cybersader/cyberbase` (not the old `awesome-cybersader`) and are built from the note's vault path at build time, never the URL slug, so permalinks and emoji folders cannot break them. View, raw and Copy pin to the vault commit being published when the build runs in the vault repository (`GITHUB_SHA`) or `CYBERBASER_SOURCE_REVISION` is set. Edit, web editor and download use `main`.
- [x] Source hosts sit behind a `SourceHost` interface. GitHub is the only provider today; a Forgejo provider would implement the same five links.
- [ ] Reaches cybersader.com only when the vault workflow's renderer pin is bumped past this change, which is its own reviewed step.
- [x] PostHog analytics carried over at the owner's request (2026-11-17), with the `publish.js` settings: Cyberbase's public project key, `https://us.i.posthog.com`, `person_profiles: 'identified_only'`, plus one page view per SPA navigation. It runs only on public builds made in the vault repository (or with `CYBERBASER_ANALYTICS=posthog`), never on owner/private builds or test builds, and `CYBERBASER_ANALYTICS=off` disables it. Providers sit behind an `AnalyticsProvider` interface.

Raw and Copy expose the whole source file, as `publish.js` already did; the vault repository is public. On the private owner site, the content security policy blocks fetching from GitHub, so Copy Markdown there opens the raw file instead.
