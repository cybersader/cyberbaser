This rehearsal lets a maintainer inspect one coherent loop: capture a synthetic authoring page, review its exact changes privately, explicitly **Publish**, and follow the existing owner job to completion. It runs the real authenticated publication routes, immutable draft and authorization store, source revalidation, and owner-controlled application pipeline.

**It is a synthetic rehearsal, not a connected authoring-workspace integration.** Publishing changes only a newly created disposable local repository and its local bare remote. Rendering, deployment, live confirmation, and local rebuild are simulated and labelled on screen. No real page has been accepted through this lane.

## Launch

From the repository root:

```bash
bun run --cwd docs review:owner-publication
```

Use an interactive terminal and a graphical display. Bun, Git, Linux `flock`, the local app dependencies, and the docs workspace's Playwright package and Chromium browser must already be installed. The launcher does not install dependencies or download a browser.

The launcher creates fresh temporary repositories and an empty private ignored store, starts loopback-only services, and opens its own ephemeral Chromium browser with a nonpersistent context. The headed context now uses the native window viewport rather than a fixed emulated size. It uses the normal one-time owner authentication flow without printing or saving the sign-in capability. It does not attach to your main browser profile. Browser requests are restricted to the fixture's own origins; its safe panel address alone does not authenticate another browser.

Keep the launcher terminal open:

- **`b` then Enter** opens a fresh isolated browser sign-in.
- **`q` then Enter** or **Ctrl-C** closes the owned browser and services and removes the temporary repositories after active owned jobs settle. Cleanup waits for active jobs for up to 30 seconds; if it cannot finish, it reports the retained temporary directory rather than claiming cleanup succeeded.

## Walk through the document-first fixture

1. Choose **Review changes**. This captures the synthetic page and prepares an immutable exact change against the pinned canonical base. **Preparation does not publish.** There is no authoring editor in this fixture.
2. Read the complete proposed document. The **Previous change** and **Next change** icon buttons focus marked blocks, with a compact total that becomes the last navigated position. The eye toggle keeps the accessible name **Show changes**, exposes its pressed state and hides or restores marks without changing the candidate. Navigation restores hidden changes before focusing a removed block. Supported additions are underlined and deletions struck through; source-only and block/exact fallbacks stay labelled. Verified inline marks show old and new text once, without a duplicate local dropdown. A local **Previous** disclosure remains for block, source-only and unsupported fallbacks that need previous exact text; full pinned/exact source is always available in Details. **Details** opens a separate native modal sheet: right-side on desktop, full-width on mobile, with initial close-button focus, contained keyboard focus and opener/scroll restoration on close. It contains the existing pinned version, comparison and exact evidence, moved as already escaped DOM without HTML injection or requests. Without JavaScript or native-dialog support, the collapsed native **Details** disclosure remains available; explicit current/compare addresses still open their requested evidence. Details is not the Publish confirmation. No display control publishes or sends a request. This is structural reading, not a Quartz preview. Tables and unsupported constructs remain labelled source. See [Review projection model](/cyberbaser/design/review-projection-model/).
3. Choose **Publish** to open a native confirmation dialog showing the page and destination. Opening it sends no publication request. **Cancel** receives initial focus; Tab and Shift+Tab stay within the dialog, and Cancel or Escape returns focus to the original action. Confirm **Publish** only when ready. Later authoring edits are not included, and source and canonical-base checks must still pass before application.
4. Follow the progress screen to **Rehearsal complete**. Exact source application, commit, and push are real, but confined to the disposable repository and local bare remote. Rendering, deployment, live confirmation and local rebuild remain simulated. **Details for the record** retains technical state and recovery information. No live-page link or real-site completion is claimed.
5. Repeated Publish requests for the same draft return the same job, not another publication. An unchanged draft with a terminal job is not a retry mechanism; preparing identical inputs does not create a fresh attempt.

A compact synthetic notice stays visible on every screen. Expand it for the full statement of real local effects and simulated stages.
