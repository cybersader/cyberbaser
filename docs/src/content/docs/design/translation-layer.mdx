Obsidian-flavored markdown contains constructs a generic markdown tool destroys on contact: wikilinks, callouts, embeds, block refs, `$math$`. The translation layer is the contract for **which of them survive the trip to the web and back**, sorted into three tiers. Since [R12](/cyberbaser/research/v1-build-plan/) that contract is enforced by *not rewriting files at all* — an edit is a raw-text splice into the original bytes, and `@cyberbaser/ofm` validates the result instead of producing it.

> [!warning]+ The one thing that would sink the project
> If a contribution path cannot change a page without damaging the rest of it, the "many independent paths" vision collapses into "one path plus some lossy alternatives." Everything below exists to make that failure detectable and then impossible.

## What actually happens to a file

A web edit does not round-trip through a parser. It finds the bytes it is allowed to change, replaces them, and leaves every other byte alone.

This is the whole design in one picture. The old plan was to parse the file into an AST and write it back out; measured against 1430 real vault files, that produced a byte-identical result **4.6% of the time** (36.9% even with stringify options tuned to this vault). The failures were formatting normalization, not construct damage, but a diff full of normalization noise is unreviewable and unmergeable. So whole-file re-serialization is out of the write path permanently.

## The tier contract

A feature's tier says how much support it gets and how much engineering it justifies.

- **Tier 1 — full, must survive an edit.** Wikilinks, callouts, image and note embeds, code blocks, math, Mermaid, tables.
- **Tier 2 — partial, never lossy.** Simple Dataview, block references, aliases, frontmatter metadata. Rendered best-effort; the source text is left alone.
- **Tier 3 — not translated, workaround documented.** DataviewJS, Canvas, Templater output, graph view.

<details>
<summary>Per-feature table: syntax, the plugin that handles it, and current status</summary>

### Tier 1 — full support

These must survive an edit from any contribution path. Rendering is the renderer's job (Quartz for the vault, Starlight for these docs); the tier is a claim about the **source file** afterwards, not about pixels.

| Feature | Source syntax | Handled by | Status |
|---|---|---|---|
| Wikilinks | `[[Page]]`, `[[Page\|alias]]` | Quartz `CrawlLinks` (vault) / `remark-wiki-link` (docs) | Shipping |
| Callouts | `> [!note]`, `> [!warning]`, `> [!tip]+` | Quartz `ObsidianFlavoredMarkdown` | Shipping |
| Image embeds | `![[image.png]]` | Quartz OFM + the spoke's `RelativeFolderLinks` transformer | Shipping, one known bug class |
| Note embeds | `![[Other Note]]`, `![[Other#Section]]` | Quartz OFM transclusion | Shipping |
| Code blocks | Fenced, language-tagged | Renderer built-in | Shipping |
| Math | `$inline$`, `$$block$$` | `remark-math` + `rehype-katex` | Shipping |
| Mermaid | Fenced `mermaid` blocks | Renderer built-in | Shipping |
| Tables | Standard markdown tables | Built-in | Shipping |

The known bug class: Quartz's `transformLink` compares a whole link target against a slug's last segment, so any target containing `/` falls back to vault-root-absolute while Obsidian means page-relative. Fixed in the spoke with a pre-`CrawlLinks` transformer (`RelativeFolderLinks`) rather than in the hub, because it is a renderer quirk. Measured effect: the attachment-link break class went 248 → 7.

### Tier 2 — partial support, never lossy

Renders *something* and may lose presentation fidelity, but must never silently corrupt the source.

- **Simple Dataview queries** — `LIST FROM #tag`, basic `TABLE`. Resolved at build time; the query text stays in the file.
- **Block references** — `[[Note#^blockid]]`. Resolved to the target block with an anchor; the block ID is preserved.
- **Aliases** (frontmatter `aliases:`) — rendered as redirect pages; frontmatter untouched.
- **Frontmatter metadata** — surfaced as page properties and badges; original keys preserved.

### Tier 3 — not translated

For each, a contributor-facing workaround, otherwise people hit a silent failure.

- **DataviewJS / complex Dataview** — use a Tier 2 query or pre-compute a static table.
- **Canvas files** (`.canvas`) — export to SVG/PNG and embed as a normal image.
- **Templater output** — render to static markdown before committing.
- **Graph view** — inherently interactive; the renderer supplies its own web graph.

Plugin execution is a closed question, not a pending one: Obsidian's CLI is real and community plugins do run through it, but it is IPC control of a running Electron app rather than a runtime, and R12 forecloses every write-path use of it anyway.

</details>

## How the contract is enforced

Three mechanical checks, all of them shipping code rather than intent:

1. **[`@cyberbaser/ofm`](https://github.com/cybersader/cyberbaser/tree/main/packages/ofm)** classifies a change between two versions of a file: `clean`, `suspect` (re-serialization fingerprints — mass churn, list-marker normalization, injected escapes), or `damage` (constructs removed or degraded, exit 1). It also carries the collision-safe masking core, which is lossless by construction over 21 fixtures and 1430 real files with zero leaks.
2. **`ofm-check.yml`** runs that classifier on every pull request against the vault.
3. **The corpus runner** re-measures byte identity over the whole vault on demand, so the 4.6% number stays a measurement rather than a memory.

The suite is 10 tests in `ofm`, part of 165 across the five packages. The classifier's first real verdict on a live contribution (PR #6, 2026-07-25) was `clean · churn 0.005 · escapes 0→0`.

<details>
<summary>The failure this design is aimed at, and the one caveat</summary>

The target is not the maintainer's own edits — those are already fine. It is any **third-party writer that re-serializes**: a git-backed CMS, a structured editor, a sync leg from another tool. The dormant Notion sync in the vault's history is the worked example: it wrote plain CommonMark with zero wikilinks (nothing OFM to corrupt), but it mirrored by delete-and-recreate, 1570 deletions in paired commits. A validator that only checked syntax would have called every one of those commits clean.

The caveat: `roundtrip()` exists in the library as a **diagnostic** and is expected to diverge on most real files. It must never be called from a write path. The README says so; this page says so; treat any future code that does it as a defect.

</details>

## Still open

<details>
<summary>Four unresolved questions, and two that closed</summary>

Open, tracked in [Open Questions](/cyberbaser/reference/open-questions/):

1. **How does a rich editor present Tier 2 and Tier 3 constructs it cannot preview?** Raw text, a locked block, a "view source" toggle? Unanswered, and it gates the in-page editing surface.
2. **What defines the splice boundary?** A reader edits a rendered paragraph; something has to map that back to a byte range in the source, including inside a callout or a list. This is the real remaining engineering.
3. **Where are backlinks computed** when the renderer is swappable — in the hub's projection, or left to each spoke?
4. **What enforces the policy?** The gates exist and classify correctly; nothing yet blocks a merge on their verdict, and naive branch protection would break the maintainer's own Obsidian Git pushes.

Closed by measurement, recorded here so nobody reopens them:

- *Is `astro-loader-obsidian` sufficient for Tier 1?* Not applicable — the vault renders through Quartz ([R14](/cyberbaser/research/quartz-spike-results/)), which scored 20/20 on the OFM checklist.
- *What is the incremental build story?* Not a problem at this scale: 933 pages build in about 160 seconds in CI, and a full OFM corpus pass over 1430 files takes 7.3 seconds on ext4. (Benchmark on ext4 — the same reads are roughly 780x slower across a 9p mount.)

</details>
