---
title: TrueNAS Custom App release rehearsal
description: Local Docker evidence for the owner-only app on an appliance-compatible layout.
---

The TrueNAS adapter keeps the node and publisher in separate container identities and runs the checked config handoff inside the app. It needs no host service or container engine socket. The HTTP endpoints bind host loopback directly, including enrollment, so the publisher can still distinguish the actual node UID.

The default Docker seccomp profile denied the nested namespace launcher on the development host. The image adds an inherited, renderer-only seccomp filter instead of relaxing the container profile. It closes non-stdio descriptors and refuses sockets except anonymous Unix stream stdio received from the runner; build descendants can use anonymous Unix pairs internally. The kernel denies opening network, netlink and named Unix sockets, outbound `connect`, and passing new socket descriptors. The stock Quartz setup/build and the configured renderer both use this launcher; native rendering is unchanged. This is socket isolation, not a new filesystem or UID boundary inside the node.

Rootful Docker 29.7 on Fedora passed the full relay-only rehearsal on the release candidate in a disposable network namespace. The fake forge exercised private site selection, manifest replay refusal, the node-versus-viewer enrollment decision and an independent signer enrollment. The publisher restarted automatically on a checked change and kept the last good config through invalid, missing and unchanged input. The private reader served pinned Quartz output on loopback, and the exact pending job survived a node restart without a push or a reader change. One synthetic signed approval led to one app push and the corresponding reader update. A configured fixture renderer served its output without reaching the fake forge, even though the node could reach it. Under Docker's default profile, the shipped launcher denied IPv4, IPv6, netlink and Unix socket creation, raw connect and addressed send while retaining anonymous subprocess IPC.

TCP was limited to application loopback ports 4517–4519 plus the fake forge's loopback port. Iroh used ephemeral IPv4 and IPv6 loopback UDP during setup and after restart. The pinned binding rejects a second IPv4 default address. The available modes are one private address with relay, relay-only, and wildcard direct. There is no wildcard fallback for a failed private bind. The appliance's Docker 28, AppArmor and middleware, live Tailscale and relay, real vault memory and actual device pairing were not exercised here.

The limits total 1888 MiB. The one-note application build reached the 1536 MiB node cap (including file cache) and served the expected Quartz output. The custom-renderer node peaked at about 98 MiB, with publisher and reconciler at about 33 and 35 MiB. These are fixture peaks, not production sizing. Monitor representative renders before enabling owner writes.

The app uses two private role UIDs and eight exact host-path mounts (many shared on just one side read-only). A networkless reconciler sees only the two isolated config directories. The publisher closes gracefully after a checked atomic replacement changes the copy's identity; Compose restarts it without engine access. Unchanged, missing or refused input cannot remove the checked output. Appliance install, reach, device onboarding, and real publishing remain separately authorized activities.
