The vault agent relayed the owner's approval to prepare the cybersader.com move, planning only.

Read once from the live Publish site: `sitemap.xml`, the site's file index (`/cache/<site uid>`) and options. Publish answers every path with its app shell and matches notes case-insensitively. The vault clone at `0cc579a` and a full local Quartz build with the current renderer supplied the new side.

Result: 920 of 1,417 notes map to a page on the new site, 497 are excluded by the July `publish.yml` boundary, none are unresolved. Three of six permalinks point at excluded notes. A three-part redirect layer (static stubs in `+` and space form, a normalized map, a `404.html` fallback) was prototyped on a copy of the build and checked with a case-sensitive static server: 1,840/1,840 stubs reach real pages, 3,680/3,680 variants covered, 497/497 retired URLs return 404 with a notice, 98% of heading links hit the exact heading id. A browser run confirmed the fragment and fallback behavior. A first run had a script bug that truncated `404.html` before patching it; caught by the browser check and fixed.

Canonical plan and values: [cybersader.com cutover sheet](/cyberbaser/development/cybersader-com-cutover/). Mapping artifacts stay in the private workspace; this public log records counts only. Nothing live changed.

## Owner decisions and the switch build

The owner kept `publish.yml` as is, accepted the three broken short links and DNS-only records. The redirect layer moved from prototype into the renderer (Cyberbaser PR #8, merged `0d0b8fa`, no effect on current builds), the site base URL became configurable and `cb-urlcheck` gained `--rebase-previous` for the domain move. Its first unit run caught `..` being accepted in a base path. The privacy concern that a plain old-path map would publish the names of the 497 retired notes was addressed by hashing keys. Vault draft PR #17 holds the switch configuration. An exact rehearsal from public sources matched the earlier results; see the cutover sheet. Nothing live changed.
