The maintainer tried the rehearsal links on his phone through the T3 Code app; they failed because the site bound only to loopback, and he noted it "should have been a tail scale link" and "needs to look good on mobile".

## Tailnet access

`try:suggestions` now accepts `--host PRIVATE_IPV4`, validated by the owner app's existing private-network rule (loopback, RFC 1918, or RFC 6598, which includes Tailscale's 100.64.0.0/10). Public and wildcard addresses are refused. The owner, reader and intake origins follow the chosen address. Rehearsal tests 19 pass, 2 opt-in skips, including tailnet and LAN acceptance and public refusal. No bootstrap or session rule changed; the one-time sign-in link now simply works from another tailnet device.

## Phone-first suggesting mode (Sol)

An iPhone 13 inspection showed four overlapping entry controls, a long inline instruction paragraph, an **Edit source** button under every block (370 on one page) and heavy heading outlines. The redesign: one **Suggest edits** entry (the forge edit link becomes quiet text and hides while suggesting), a safe-area-aware bottom toolbar with the toggle, change count and **Review & send**, a one-time dismissible hint, **Edit source** only for the active block, collapsed change sheet, full-height review sheet on phones and side panel on desktop, subtle active-block highlight, 44 px targets, 16 px inputs and dark-theme styling. Integrity behavior is unchanged.

Renderer suite passed; the offline Quartz browser run covered iPhone 13 emulation and 360 to 1280 px widths. Coordinator check of the live tailnet site at iPhone size: no horizontal overflow, clean top, hint and toolbar visible. Physical iPhone Safari, the software keyboard and real safe-area behavior remain unverified.
