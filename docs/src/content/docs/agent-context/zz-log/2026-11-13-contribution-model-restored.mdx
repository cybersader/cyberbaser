## Maintainer correction

The maintainer clarified that the previously referenced SSO service was deployed alongside another tool and is not wanted for this setup. They prefer a basic embedded Better Auth system. They also challenged the discussion's narrowing to owner authentication and deployment when the project already had broader contribution workflows, richer authoring, trust, sharing and governance designs.

This supersedes the earlier same-day conditional shared-SSO recommendation, not the findings of the sibling source inspection. It does not authorize implementation, select registration/factors/roles, or require public contributors to create accounts.

## Recovered model

The canonical [contribution, trust and access map](/cyberbaser/design/contribution-trust-and-access/) reconnects the existing vision, workflow inventory, proposal operating model, architecture plan, federated-identity research and legal/governance pages:

- owner-local direct authoring remains distinct from external proposals;
- account-free suggestions, richer trusted-contributor authoring, forge editing and agent proposals remain separate intended experiences;
- identity, private-content access, trust routing, integrity, owner decision, application and publication are independent boundaries;
- trust earned through contribution history and visible credit remain intended but incomplete, not replaced by login;
- publication selection differs from private RBAC and cross-base federation;
- rich presentation remains allowed while whole-file regeneration remains prohibited; and
- implemented packages and synthetic mechanics do not establish an offered public lane or independent-human acceptance.

Older vision and architecture pages contain historical status statements. This recovery uses the later recorded Apply/inbox/private-suggestion milestones rather than resurrecting their earlier pending state. Historical selective-publication proposals are not fresh permission to split repositories or move source. No live workflow or ledger status was rechecked.

## Authentication boundary

The current [authentication assessment](/cyberbaser/research/authentication-reuse/) and [setup plan](/cyberbaser/development/real-owner-setup-plan/) now prefer embedded Better Auth and remove upstream-provider discovery as the next identity task. Existing architecture rules against identity custody and durable browser credentials still require explicit reconciliation with a replaceable local account component before implementation. No account storage was added to the owner app or pure proposal core.

## Evidence and limits

This was documentation recovery and synthesis, not another delegated research wave. Canonical pages and `.claude/` orientation were aligned in the same session. Scoped whitespace and local-link checks accompany the update; no application tests, full docs build, browser work, real authentication, source writes, containers, installation or publication were performed. Existing live-execution holds remain unchanged.
