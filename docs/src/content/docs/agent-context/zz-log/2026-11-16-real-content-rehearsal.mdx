## Real content in the hands-on rehearsal

By maintainer direction to keep moving, two Sol workers ran in parallel.

- **`--from` / `--folder`:** `bun run --cwd docs try:suggestions --from "<vault>" --folder "<folder>"` copies one folder's Markdown plus the attachments its pages reference, read-only from a Git ref (default `origin/main`, overridable with `--ref`). The source's working tree, index, refs and mtimes are verified unchanged. Caps: 400 Markdown files and 50 MiB each for Markdown and attachments. Publication denies still apply; cross-folder links stay unresolved; content is never rewritten. Tests: 17 pass, 2 opt-in skips; opt-in real Quartz 19 pass, both covering submit, limit, approval, apply, local push, rebuild and cleanup. The workers did not run it against the real vault.
- **Selection prefill:** selecting text in the article fills **Text to replace** when the form opens; **Use selected text** recaptures it explicitly and never silently overwrites typed text. Only whitespace is normalized. Renderer suite passed. Real-browser and mobile selection timing remain unverified.

## Finding: Windows line endings

The existing apply step accepts only LF source (`source-not-lf-only`). Read-only count at the vault's `origin/main`: 4 of 57 notes in `📁 03 - Curations, Stacks` and 14 notes vault-wide contain carriage returns. Those notes can receive suggestions but cannot be applied until normalized in the vault.
