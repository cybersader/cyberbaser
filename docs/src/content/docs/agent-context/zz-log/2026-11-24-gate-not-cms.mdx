## What prompted it

The owner asked whether Cyberbaser can support modular additions like author pictures, as the Cyberchief site has, and then whether authentication carries profile data and whether authoring has data models for fill-in fields (cover image, profile picture, tags). The Cyberchief project lead separately asked what the owner's father, a non-technical author, would actually do to write and publish.

## What is true today

- Cyberchief's author picture is a site customisation: name and credential are component defaults, photos are copied in by its setup script.
- Cyberbaser identity is a device key, a pairing label and an access level. GitHub sign-in authorises the publisher to push and creates no person record.
- The property rule deliberately names no keys, so there is no content model.
- The writing tool publishes edits to existing notes only (rehearsal, 96 of 96). Creating notes and carrying images are not built.
- The one-app ships one pinned Quartz renderer; a vault can bring a stylesheet but not components, so Cyberchief's custom site cannot be published through it yet.

## The comparison shown

Six architectures, each as a row of seven jobs (writing screen, fill-in fields, what a post contains, people and photos, approve and publish, storage, site look) coloured by owner: WordPress, Obsidian Publish, a Git-based CMS (Decap, Pages CMS, Keystatic), and three Cyberbaser shapes: A the gate, B gate plus content model, C meta-CMS. Each row carried one sentence on what the father would do.

## Decision

The owner chose A: "Definitely A, and I'm not saying owning forms, I'm really just saying owning a meta schema or I don't know". Recorded in `.claude/41-QUESTIONS-RESOLVED.md`.
