## Why this handoff exists

Cloud coding sessions start from a GitHub clone, not the maintainer's uncommitted local working tree. The local WP5 queue-review and UI research wave therefore needs a reviewable draft branch before separate cloud sessions can inspect it. This packaging step does not merge, install, deploy, enable an intake lane, or authorize an approved proposal to write source.

The follow-up sessions have distinct bounded jobs: one adversarially inspects whether intake or the decision store can reach canonical writes or publication, and fixes verified defects with tests; the other prepares questions, fixtures, and pass/fail criteria for the maintainer checkpoint. Preparing that checkpoint does not run or pass it.

## Corrections during packaging

- The owner-alpha OCI build-context allowlist omitted the new `@cyberbaser/review-projection` dependency. The allowlist and structural test now include its package and source, and the owner-alpha container workflow watches changes to it.
- Both review JSON paths were inspected. The list explicitly selects summary and verification fields, while detail explicitly omits the new bounded reading document. A test injects sentinel reading text and checks that neither JSON response exposes it. Authenticated HTML review still presents the reading text by design.
- Canonical research and chronology now point at `packages/review-projection/src/` after extraction from the static mockup. An earlier unqualified claim that the JSON response was byte-identical is replaced with the specific projection behavior tested above.
- The first draft PR CI run found a cross-platform acceptance-test assumption: a read-only Git status refresh may chmod `.git/index` from 0644 to 0600 while leaving its bytes unchanged. The no-effect snapshot now ignores only that internal index mode, still compares its bytes and size, and still compares all canonical file modes, source bytes, Git refs, index entries, and status.
