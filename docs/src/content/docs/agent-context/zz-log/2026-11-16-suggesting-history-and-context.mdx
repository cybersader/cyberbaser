The maintainer found the hover-following source affordance awkward, could not undo edits on iOS, and asked for protection against losing unsent suggestions plus readable, removable review changes. This wave changes the reader interface, not the owner-controlled source boundary or the offered-lane policy.

## Reader behavior

- Hover does nothing. The caret’s block gets a faint 2 px left rule and a small `</>` control named **Edit Markdown for this block**. The control takes no flow space, uses a document-overlay layer so callouts and table overflow cannot clip it, has a 44 px coarse-pointer target, and moves to the top-right on narrow phones. The badge counts changes in that block.
- Derived or unmapped text opens an anchored **This part comes from Markdown.** prompt with **Edit Markdown**. Escape, an outside pointer action or moving the caret away dismisses it. Safety-refused blocks say **This block can't be edited here** and offer no editor. There are no disabled **Source unavailable** chips.
- The toolbar adds **Markdown**, **Undo** and **Redo**. Shortcuts are Ctrl/Cmd+Shift+M, Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z and Ctrl+Y. Browser history-input events route into the same draft history. The existing touch-focus rule still hides the toolbar while a suggesting surface has focus.
- History snapshots contain the existing exact-operation ledger, comments and caret coordinates, not a second text model. Typing coalesces at the same caret until a pause over one second, a caret jump or another editing action. Deletions, Markdown **Done** and **Remove** create individual steps. The in-memory history is capped at 100 steps; draft persistence is unchanged and history itself does not survive reload.
- Full unloads with changes request the native browser warning. Internal links are intercepted in capture phase before pinned Quartz’s window-level handler, which ignores `defaultPrevented`. **Stay** keeps the draft; **Discard and leave** clears this page’s draft and replays the approved link through Quartz. No changes means no prompt. This covers link-driven SPA navigation, not programmatic navigation or browser-history traversal.
- Review cards show the nearest preceding section heading and about 60 characters of surrounding text on each side, with the exact change inline. **Remove** reverts that operation in the page and ledger and is undoable. Removing the last change closes review.
- The rehearsal launcher now says to tap **Suggest edits**, tap into text and type, then choose **Review & send**. That wording lives in `suggestions-rehearsal.js`, not the fixture module named in the initial brief.

## Integrity boundary

No serializer, source writer, dependency, publication setting or authority changed. Hidden source remains omitted by provenance. Stale or ambiguous mapping still refuses edits. Rendered and Markdown changes still cannot mix within one block. The five-field source-bound operations and owner application path are unchanged.

## Coordinator check on the real page and iOS Safari

On the live private rehearsal of a real Cyberbase page (desktop Chromium), hovering blocks moved nothing and showed no button, the caret marker appeared, and Undo and Redo worked. On an iPhone 18 Pro iOS 27 simulator (real WebKit) the new toolbar fit, but two defects appeared and were fixed directly:

- The phone placement of the `</>` marker (top-right overlay) covered the words being typed. Phones have no gutter, so the marker is now hidden at 600 px and below; the toolbar **Markdown** button and the contextual prompt cover that case. The first attempt scoped the rule under `.cb-suggesting`, which missed because the controls now live in the document overlay layer.
- Tapping toolbar Undo reopened the iOS keyboard because restoring the caret refocused the page. Toolbar Undo and Redo on touch devices now skip refocusing when the page was not already focused.

Re-verified on the simulator: the typed insertion is visible in green, and toolbar Undo reverts it to 0 changes with the keyboard staying closed. Renderer suite and browser acceptance pass after the fixes. Still open: unmapped text spans are exposed to assistive technology as buttons with internal labels such as "transformed source atom", which needs plain wording.
