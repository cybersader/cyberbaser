## What cyberbaser is

Cyberbaser is **an interoperability layer for contributable, version-controlled knowledge bases.** It sits between the surfaces people author from, the systems that publish their work, and eventually other independently owned knowledge bases. It is general-purpose, not tied to one domain or one authoring tool. Obsidian is first-class, and [`cybersader/cyberbase`](https://github.com/cybersader/cyberbase) is the first dogfood vault rather than the scope.

The current v1 interpretation is an **owner-controlled change boundary** around a version-controlled knowledge base. Reader correction controls, trusted rich browser or CMS-like tools, forge editors, local Markdown tools, and agents may all be replaceable authoring spokes. External spokes submit bounded, exact source-bound proposals; the owner keeps direct local authoring and the final decision. Renderers and hosts remain independently replaceable output spokes.

GitHub, GitHub Actions, Pages, and pinned Quartz implement the working dogfood path. They are current infrastructure, not the product essence. [Architecture shows what is actually built and borrowed](/cyberbaser/design/architecture/).

Two repos, easy to confuse:

| Repo | Role |
|---|---|
| [`cybersader/cyberbaser`](https://github.com/cybersader/cyberbaser) (this repo) | The change-boundary packages, renderer adapters, research, and canonical project knowledge base |
| [`cybersader/cyberbase`](https://github.com/cybersader/cyberbase) | The dogfood content vault: plain Markdown, one example, not the scope |

## Current phase: v1 Build

Research & Foundations closed on 2026-07-25. The live dogfood stack selects and projects 933 Markdown sources into 931 public page URLs and has rehearsed the GitHub-backed contribution loop twice. What has **not** shipped is the account-free path for a reader or a general operating model for a maintainer who does not use GitHub.

[`OD-01`](/cyberbaser/research/owner-self-dogfood/) completed the one real owner loop required in this phase. The immutable charter remains historical evidence; `OD-02` and `OD-03` are **Not run — superseded**, with stale-source, ambiguity, and rejection-path binding covered by synthetic mechanical `ADV-*` scenarios only. No human owner rejection occurred. The private owner-alpha wiki, automatic exact-change pipeline, safe restart recovery, deployment/live verification, and hermetic browser rehearsal are implemented, and the first real policy-activated Cyberbase Save/push completed on 2026-08-02 with a verified commit, normal push, successful deployment, and confirmed live transition. Routine owner use is current. The owner-alpha route is a selected owner-local policy-bound writer; external proposal spokes remain no-write. The local seven-field form, review card, and `@cyberbaser/correction` primitive remain instruments, not a shipped external editor, contribution product, or generalized adapter API. The five-reader, one-independent-owner protocol is preserved for later if stronger usability claims need it, and Q09 remains open.

Federation remains the long-term non-central seam. The five-origin fixture is controlled local evidence only; provisional profile work waits for a concrete need from an independently operated peer.
