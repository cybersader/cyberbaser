Cyberbaser is an **interoperability layer for contributable, version-controlled knowledge bases**. The contributable-wiki capability is what that layer enables: the current build uses Obsidian (and other markdown surfaces) as a first-class authoring surface and a Git-backed vault as today's source of truth. The GitHub-backed contribution path exists; the account-free product path has not shipped. One real [owner self-dogfood](/cyberbaser/research/owner-self-dogfood/) loop is complete, and the private owner-alpha wiki now automates the exact source-to-live mechanics behind one owner Save. Its first real policy-activated acceptance Save completed on 2026-08-02 with a verified commit, normal push, successful deployment, and confirmed live transition; routine owner use is current. The shared external proposal contract, Forgejo Lane A adapter, local carrier-neutral queue, account-free Lane B adapter/app, disabled Quartz form, local-only sibling-service deployment bundle, and same-host owner review with immutable decision-only records are implemented and mechanically tested at their stated layers. Neither lane is offered: Lane A is not live-validated or installed, and Lane B is off by default, unexposed, and human-untested. Q09 remains open. The larger [concierge pilot](/cyberbaser/research/concierge-human-correction-pilot/) is preserved as an optional future evidence gate before broader usability claims. The roadmap reflects this: research and architecture come first, features are built on that foundation, and every significant decision is [logged with rationale](/cyberbaser/agent-context/zz-log/).

See the [vault vision mining](/cyberbaser/agent-context/zz-log/2026-04-13-vault-vision-mining/) for the original dream, and the [vault tech stack mining](/cyberbaser/agent-context/zz-log/2026-04-13-vault-tech-stack-mining/) for the 300+ curated links that seed the research below.

This page is the **living roadmap** — only active and future phases live here. Every significant decision gets a dated entry in the [decision log](/cyberbaser/agent-context/zz-log/). Link roadmap items to their log entries so the *why* is always reachable from the *what*.

## Current phase: v1 Build (foundations closed 2026-07-25)

**If you're returning after a long gap, the arc so far in five sentences.** The research phase settled the identity (an interoperability layer, not a publishing tool), proved a masking layer that protects Obsidian syntax through a Markdown parser, and wrote the foundations. An adversarial pass then [audited the plan itself](/cyberbaser/research/plan-critique/) and produced [three competing designs for what v1 is](/cyberbaser/research/v1-build-plan/). Rather than argue, we ran the deciding measurement against **all 1,430 real vault files**: whole-file serialization returned 4.6% byte identity, so no Cyberbaser-mediated source update or adapter writing on the owner's behalf may regenerate the untouched file. That locked the v1 shape ([R12](/cyberbaser/research/v1-build-plan/#gate-result-run-2026-07-25)): **byte preservation by construction**, **mechanical validation**, and governance on top. R12 constrains source emission, not presentation, so rich browser, WYSIWYG, or CMS-like authoring remains possible through a conforming exact-proposal adapter.

### Building now

- [x] **Byte-preserving foundation** — `@cyberbaser/ofm` is a validator, never a writer; the publish boundary, projection, Quartz spoke, link checker, and trust classifier are built. The live vault proves the GitHub-backed dogfood path, not the general product.
- [x] **Owner self-dogfood phase closed by supersession.** `OD-01` completed one genuine reader-to-live owner loop. The immutable three-ID charter remains historical evidence; `OD-02` and `OD-03` are **Not run — superseded**, not completed. Deterministic `ADV-*` scenarios now cover stale source, ambiguity, and rejection-path binding as synthetic mechanical evidence only. No human owner rejection occurred. [Result and limits](/cyberbaser/research/owner-self-dogfood/).
- [x] **Build the private owner-alpha wiki and automatic exact-change pipeline.** The owner can launch one private app (loopback by default, or one owner-chosen private network address), browse the real Quartz-rendered Cyberbase, open an existing source-backed Markdown page, and click **Save and publish** once. That Save is the per-edit authority event; a strict durable local policy performs the safety checks, exact source application, one-path commit, normal push, exact Actions-run monitoring, live witness verification, and local rebuild without routine stage approvals. External authoring spokes remain proposal-only. Fixture, package, and pinned-render verification are complete, and the first outward real Cyberbase Save/push completed on 2026-08-02 under the explicitly activated durable policy.
- [x] **Implement, install, and publish the first [decision ledger](/cyberbaser/design/decision-ledger/) observation (WP1).** The selected two-stage design is built: a permissionless `pull_request: closed` capture emits only a non-authoritative routing hint, and a trusted `workflow_run` recorder binds the exact run/artifact, reconstructs authority from GitHub APIs and exact Git objects, and publishes one ledger-only non-force commit. Hermetic acceptance covers maintainer, fork, closed-unmerged, duplicate, and tampered-artifact scenarios. The two reviewed workflows are installed in Cyberbase. After two fail-closed live integration repairs, Capture run `31648052403` and Record run `31648065388` published one valid unclassified maintainer row. No real fork case has run, and the 20-classified-observation precondition remains at zero.
- [x] **Build and mechanically accept WP2 container packaging.** One local-only Linux/amd64 OCI image now serves owner always-on operation through explicit rootless and rootful Docker Engine profiles, Linux host networking, exact mounts, a profile-bound state volume, socket-only HTTPS credentials, attached bootstrap re-arm, and readiness-aware recovery. Package, fixture Save, replacement, and image-level acceptance passed within the [documented evidence boundary](/cyberbaser/development/owner-alpha-container-deployment/#evidence-boundary). No physical-device Save, external-forge/live-site container Save, registry publication, or service installation is claimed.
- [x] **Complete WP3 phase-one acceptance.** The strict Forgejo 16 adapter and disposable one-time-seeded fixture passed on 2026-08-10. The rejected same-UID host runner was replaced by unprivileged run-scoped job containers with an exact two-source volume allowlist and no engine socket. The isolation probe, `ofm-check`, `trust-gate`, merge publication, exact owner-alpha Save, fixed run/job binding, HTTPS witness, unchanged seed authority, storage ceiling, and manifest-bound cleanup all passed on Forgejo 16.0.2. Peak combined temporary storage was 172,289,041 bytes, and no labelled resources or run roots remained. Authority cutover remains a separate explicit decision. [Implementation and evidence](/cyberbaser/development/forgejo-phase-1/).
- [x] **Implement the shared WP4 proposal contract.** `@cyberbaser/proposal` now canonicalizes one pinned existing Markdown source, one fully prepared quote- or offset-bound splice, submission metadata, evidence URLs, and an optional inert identity claim. It applies only in memory and feeds a separately receiver-verified subject into the existing trust classifier. It contains no queue, endpoint, Git/forge adapter, identity verifier, source writer, or publication authority. [Contract and evidence boundary](/cyberbaser/design/proposal-contract/).
- [x] **Implement and hermetically test the [Forgejo Lane A adapter](/cyberbaser/development/forgejo-intake-adapter/).** `@cyberbaser/forgejo-intake` reconstructs one canonical proposal from injected authoritative Forgejo metadata and real local Git objects, reads trust only from the exact base commit, and performs no API or source mutation. It is not validated against a live Forgejo instance, installed, linked from rendered pages, offered to contributors, or production authority.
- [x] **Implement the WP4 local queue and [account-free Lane B mechanics](/cyberbaser/development/account-free-intake/).** `@cyberbaser/proposal-queue` retains exact carrier-neutral proposals in one finite owner-local queue. `@cyberbaser/account-free-intake`, the separate optional Bun app, disabled Quartz form, and local-only OCI/Compose bundle carry one strict anonymous intent through exact retained source into `pending-review`. The no-R-number implementation amendment selects a local filesystem queue and sibling service for v1. These layers are mechanically tested, disabled by default, and do not apply or publish source.
- [x] **Implement same-host owner review and immutable decision-only records in the local working tree.** The running intake writer retains its lifetime queue lock while a private Unix socket serves bounded read-only snapshots. Owner-alpha independently revalidates exact source, policy, trust, classification, and expiry evidence, then records one exactly-once approval intent or rejection in its ignored local store. The acceptance proves restart recovery, history after queue purge, continued intake, and zero source, Git, queue-lifecycle, deployment, publication, rebuild, or owner-job effects. This wave is not yet committed, merged, or deployed.
- [x] **Synthesize the proposal operating model before extending the authority path.** The [working model](/cyberbaser/research/proposal-operating-model/) separates submitted intent, exact change sets, and owner operating evidence; recommends a single-existing-file multi-operation successor to version 1; defines realistic fixture and deployment matrices; and records the adversarial limits. No version 2 schema or taxonomy is locked by the research alone.
- [x] **Produce realistic fixtures and a coherent static review mockup.** The private typed corpus covers six real proposal-v1 cases, two noncanonical single-file multi-operation targets, conceptual broader scope, blocked evidence, authority axes, and adversarial inputs. The separate loopback-only static surface now shows simultaneous Current and Proposed proof on wide screens, equivalent mobile stacking, complete atomic scope, deliberate in-memory decision previews, a truthful inbox plus Evidence lab, and selectable system boundaries. Adversarial review defects were repaired and focused mechanical checks pass. This is synthetic-mechanical and static-design evidence only.
- [ ] **Pass the focused maintainer comprehension checkpoint.** The maintainer must unaided identify the proposal, complete scope, Current versus Proposed, required action, approval effects and non-effects, blocked versus rejected, support level, and system placement. Automation and screenshots cannot pass this gate.
- [ ] **Select the richer contract, then build the approved-proposal pipeline adapter.** Only after the checkpoint may the project lock proposal-v2 shape, taxonomy, limits, or rendered-context boundaries and refactor the real owner presentation. The later adapter must consume exact decision evidence without treating approval intent as source-write authority, rerun current eligibility checks, and prepare a separately authorized owner pipeline input. A connected contributor-to-live slice follows only after that boundary is proven.
- [ ] **Turn neither Lane A nor Lane B into an offered path by implication.** Any live Lane A compatibility/installation step is separately authorized. Lane B still needs a deliberate reverse proxy/TLS/edge-abuse design, public deployment authorization, and human evidence. Q09 remains open, owner-alpha remains the separate direct-authority writer, and the preserved five-reader protocol remains optional before any unfamiliar-reader or independent-owner usability claim.
- [ ] **Make enforcement honest without breaking daily authoring.** `ofm-check` remains report-only, the trust route remains decision-only, and direct maintainer pushes need a compatible validation path. See [Q10](/cyberbaser/reference/open-questions/#q10--what-enforces-the-moderation-policy).
- [ ] **Close the general-maintainer gap.** The dogfood stack still assumes GitHub and Actions. The pilot tests one local, non-GitHub review-and-apply workflow, but does not choose or ship the hosted, one-click self-hosted, or local-first operating model.
- [x] **Define stable URL continuity (R23).** Public URL continuity is checked at the emitted-site boundary rather than by forcing one permanent source slug scheme. `@cyberbaser/linkcheck` compares previous and candidate sitemaps, verifies candidate routes, and requires direct same-origin redirect coverage for every removed canonical URL. A local comparison preserved all 931 current public URLs and exercised one real Quartz alias stub; no deployment or public URL changed.
- [x] **Install the live URL continuity gate.** Cyberbase commit `dd576cd` retained the cumulative 931-URL baseline and pinned Cyberbaser `eac9f1f`. Run `31540402789` passed `cb-urlcheck` before Pages artifact upload with all 931 URLs unchanged, then deployed successfully.

The five-origin federation fixture remains **controlled local evidence only**. It does not create an interoperability claim or an immediate protocol workstream. Extracting and publishing a provisional profile waits until an independently operated peer demonstrates a concrete need to implement against it; the fixture can supply test material if that need appears. [Federation result and limits](/cyberbaser/research/federation/#measured-local-fixture-the-narrow-claim-passed).

### Reopened research (deleted in error 2026-07-25, restored 2026-07-26)

A knowledge-ops commit removed these open research tasks with no decision record. One of them, operational model and sustainability, was added by the maintainer deliberately (db015a2) and is a paraphrase of the question that triggered the 2026-07-26 alignment pass. They are open questions, not completed work.

- [ ] **Operational model + sustainability**: where does the sustained work live in cyberbaser? Which layer creates enough value that someone would pay to not build or maintain it? Candidate value centers: the translation/validation layer as a library, a contribution widget, plugin execution in CI, a hosted service, an enterprise tier. Informs license choice and what to protect versus give away. Intertwined with identity: "what is cyberbaser" and "what's the business" answer together. See [challenge 01](/cyberbaser/agent-context/zz-challenges/01-identity-operational-model/), only 2 of 6 deliverables ever produced.
- [ ] **Competitive counter-argument**: [challenge 01 item 5 and challenge 04 item 4](/cyberbaser/agent-context/zz-challenges/04-competitive-landscape/) both asked "what if Quartz + a CMS + GitHub Pages already covers 90% of this for free?" The project has since shipped approximately that configuration and never wrote the answer. The comparison table both briefs asked for does not exist.
- [ ] **Broader contributor attribution** ([challenge 07](/cyberbaser/agent-context/zz-challenges/07-contributor-attribution/)): R24 closed Q08 by proving that the measured one-commit GitHub fork-and-squash path preserves the contributor as the authoritative commit author. Visible page credit, contributor profiles, anonymous and pseudonymous credit, multi-commit and cross-forge behavior, and trust-history computation remain open. Attribution is not only vanity: contributor history is still the trust curve's missing computed input.
- [ ] **Publish site survey**: reader-experience patterns from published Obsidian sites (navigation, search, mobile, backlinks, attribution).
- [ ] **Data sync strategy**: media at scale, and the failure modes of content flowing between authoring surfaces.
- [ ] **SEO baseline**: partially delivered for free by the Quartz spoke (sitemap, RSS, OG images, alias redirects) and never recorded as delivered.

### Publish the real vault
The real vault is live through the publish boundary, and R23 now protects its cumulative public-address history before every Pages publication. The first required run preserved all 931 canonical URLs and deployed successfully. Future canonical additions are appended to the baseline; historical entries remain even when served by redirects. (The old "translation layer spike" phase was deleted by R12: forward rendering is bought from the commodity renderer, and the reverse direction needs no serializer because nothing re-serializes.)

### Contribution beyond the maintainer
Use the private owner-alpha wiki for real owner corrections and fix only friction or safety defects observed in use. It is a private owner-local source editor and policy-bound writer on an owner-chosen private network address, not an external contribution surface. WP4's account-free endpoint, local queue, and disabled renderer form are implemented only as off-by-default local mechanics; they are not publicly deployed, offered, human-tested, or authorized to write source. The same-host owner review and immutable decision-only surface is mechanically accepted, but it is not connected to source application or evidence of unfamiliar-reader or independent-owner usability. If Cyberbaser later needs to claim that unfamiliar readers can use a path unaided or that a separate owner can operate it, run the preserved [concierge correction pilot](/cyberbaser/research/concierge-human-correction-pilot/) before making that claim. No external rich editor, hosted moderation surface, or generalized authoring-adapter product is shipped.
