### [R23] Stable URLs are an emitted-site continuity invariant, not a permanent slug scheme
- **Asked:** 2026-04-11 (Q06) · **Resolved:** 2026-08-11
- **Answer:** Freeze continuity at the emitted-site boundary. The current case-preserving routes emitted by pinned Quartz from the projected source paths are the live baseline. A candidate publication may add canonical URLs freely. Every URL in the reviewed previous sitemap must either remain canonical or remain available as one direct redirect stub to exactly one current canonical URL on the same HTTPS origin and under the same base path. The stub must contain `noindex`, exactly one canonical link, and one zero-delay refresh to the same target. Missing candidate routes, canonical routes that are themselves redirects, uncovered removals, malformed or duplicate inventories, origin or base-path drift, unsafe percent escapes, query or fragment targets, and redirect chains fail closed.
- **Rationale:** URL continuity is the durable reader-facing property; source naming, slug algorithms, and renderers are replaceable implementation choices. This preserves R16 and R19: the live site continues using verbatim path-derived URLs with exact case, natural vault names remain untouched, and a future renderer or naming policy may change only with explicit redirect evidence. Source `aliases` or `permalink` values may help a renderer emit redirects, but they are not canonical route authority. Neither is `publish.report.slugs`; the renderer's emitted sitemap is the canonical page inventory.
- **Implementation and evidence:** `@cyberbaser/linkcheck` exports `parseSitemap`, `checkUrlContinuity`, and the `cb-urlcheck` CLI. It compares previous and candidate sitemap inventories against candidate emitted files and writes a deterministic schema-version-1 report. The package suite passes 24 tests. A read-only copy of the public Cyberbase sitemap contained 931 URLs; a local case-preserving projection of the current public vault rendered through pinned Quartz v4.5.2 also contained 931, with 931 unchanged, zero added, zero removed, and zero failures. One real emitted Quartz alias stub separately passed the removed-route check. Lowercase projection remained disabled.
- **Live installation evidence:** Cyberbase commit `dd576cd5ed3aa7c4f85b57689759dfeea62857f7` added the cumulative 931-URL baseline and pinned Cyberbaser commit `eac9f1fb1947d60b084cdbf92cbb997844732640`. GitHub Actions run `31540402789` ran `cb-urlcheck` before Pages artifact upload, reported 931 previous, 931 candidate, 931 unchanged, and zero failures, then completed Pages deployment `5859387327`. The public sitemap retained the same exact-case URL inventory; no source path, URL, or redirect changed.
- **Consequence:** Q06 and its live-enforcement residue are complete for the Cyberbase dogfood deployment. Future canonical additions must be added to the cumulative baseline, while historical entries remain protected even after they become redirect routes. The five-origin federation fixture remains test scaffolding and supplied no production URL authority. Q08 later closed through R24; Q09 and Q10 remain open.

### Amendment — owner-alpha binds one owner-chosen private address, transport-neutral (2026-08-02, no R-number)
- **Maintainer direction:** Extend the private owner-alpha wiki beyond one desktop so the owner can use it from their other devices over a private network (a Tailscale-style encrypted overlay in practice), with the explicit constraint that the platform must never become opinionated around or limited to Tailscale.
- **Mental model (communicate it this way):** the owner's machine is a small personal wiki server — the same self-hosting pattern as Jellyfin or Home Assistant. Other trusted devices are just browsers on the private network: notice a mistake on the phone, tap Edit, fix, tap Save once; the server (which alone holds the vault, Git, and credentials) verifies, applies, publishes, and confirms live. Noticing and fixing become the same moment, from anywhere on the owner's network.
- **Selected capability:** `listen.host` accepts exactly one private numeric IPv4 address: loopback `127.0.0.0/8` (default, unchanged), RFC 1918 (`10/8`, `172.16/12`, `192.168/16`), or RFC 6598 shared address space `100.64/10`. Hostnames, IPv6, wildcard, public addresses, exact range endpoints, and default-HTTP port 80 fail closed. Both origins bind the exact address, never `0.0.0.0`. Product code carries no overlay-vendor API, CLI, or hostname; vendor names appear only in operating docs as examples.
- **Session model:** Each consumed one-time bootstrap now creates a distinct device session with its own cookie and CSRF token (bounded set). Entering `b` at the server console mints a fresh one-time sign-in link for another device; re-arm replaces only the unused link and never signs out active devices. Restart revokes all sessions and is the only revocation mechanism. No HTTP route can mint capabilities.
- **Trust assumption, stated:** Transport stays plain HTTP; on a non-loopback address, confidentiality and integrity come from the chosen private network (encrypted overlay, or a LAN trusted with those bytes), not the app. Never exposed to the public Internet.
- **Mechanical consequences:** The listen identity was already part of the policy revision, so an address change changes the durable policy and forces a full owner-site rebuild with the new exact edit-link origin.
- **Non-consequences:** This changes reachability for the owner only. It does not create a hosted service, external intake endpoint, account-free path, multi-user authorization model, or any Q09 progress, and external spokes remain no-write.

### [R12] The v1 shape (resolves the R09 gate)
- **Asked**: 2026-07-25 (R09) · **Resolved**: 2026-07-25, same day, by measurement
- **Answer**: **Byte-preservation by construction, validation as the product.** Pipeline D over all 1430 real vault files: **4.6% byte-identical**; vault-tuned stringify options reached only **5.1% exact byte identity** and **36.9% after trailing-whitespace normalization**. There were zero mask leaks and zero parse errors; failures were dominated by formatting normalization, not OFM damage. Both decision-rule branches had a false premise: the serializer isn't "unbuilt," it's *unbuildable as a whole-file re-serializer* — AST round-trips are architecturally incapable of byte fidelity on real formatting diversity. Locked: (1) **no whole-file re-serialization in the write path, ever** — raw-text splice-only editing (GitHub web editor interim, CM6 raw widget later); (2) **`@cyberbaser/ofm` is a validator, not a writer** — corpus runner + diff classifier + masking core, aimed at third-party writers that DO re-serialize (CMS candidates, Notion sync); (3) the moat restated as byte-preservation + mechanical validation + governance.
- **Rationale**: the gate measurement (R09 procedure, results in `/cyberbaser/research/v1-build-plan/`). The dissent's prediction confirmed: 20/21 was a property of fixtures written in remark's output style. **R05's consequence was over-claimed** — the spike proved masking protects OFM constructs through a parse (true, still stands), not that real files round-trip (false).
