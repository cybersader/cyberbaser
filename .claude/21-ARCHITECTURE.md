## Current truth (summary, 2026-08-11)

- **Mental model:** replaceable external authoring spokes → pinned, bounded proposals → owner-controlled publication/exact-change/integrity/trust boundary → one authoritative Markdown source → replaceable rendering and publication spokes.
- **Owner lanes:** the owner may author directly in a preferred local Markdown tool or use the private owner-alpha wiki. In owner-alpha, one Save is the authority event and a durable policy controls the exact source-to-live operation. Mental model: the owner's machine is a small personal wiki server (self-hosting pattern); their other trusted devices are just browsers on a private network — edit from the phone, the server holds the vault/Git/credentials and does the work.
- **External lanes:** reader controls, rich browser/WYSIWYG/CMS-like tools, forge editors, and agents may use arbitrary presentation or transient models, but their adapters cannot directly write canonical files, become a second authority, authorize themselves, or hide stale/ambiguous source mapping.
- **URL continuity:** R23 makes previously published canonical URLs an emitted-site invariant independent of source layout and renderer metadata. Cyberbase now retains a cumulative 931-URL baseline and runs pinned `cb-urlcheck` before Pages artifact upload. The first required run passed with all 931 URLs unchanged and deployed successfully.
- **As built:** ten no-authority boundary packages (`correction`, `proposal`, `forgejo-intake`, `account-free-intake`, `proposal-queue`, `ofm`, `publish`, `projection`, `linkcheck`, `trust`), the append-only `ledger` package, the private authority-bearing `owner-alpha` application, the separate optional no-authority `account-free-intake` application, GitHub and Forgejo deployment-observation providers, and dogfood/read-only CI jobs. `correction` remains the pure exact-splice primitive. `proposal` is the pure canonical external adapter-output contract and accepts receiver-verified trust subjects separately from inert identity claims. `account-free-intake` derives anonymous proposals from retained exact source, while `proposal-queue` retains finite review evidence. The sibling intake app is disabled by default and separate from owner-alpha. Only the separately selected owner-local route performs policy-bound source application. The ledger's two-stage GitHub adapter is implemented and hermetically tested: Stage A carries only a non-authoritative routing hint, and trusted Stage B reconstructs authority from GitHub APIs and exact inert Git objects before one ledger-only non-force publication. It is not installed in the live vault, has had no real fork run, and has zero live observations. The Forgejo 16 provider and disposable one-time-seeded fixture are implemented and accepted within a controlled local boundary. The rejected same-UID host runner was replaced by unprivileged run-scoped job containers with an exact two-source mount allowlist and no engine socket. On 2026-08-10 Forgejo 16.0.2 passed the isolation probe, controlled PR gates, exact owner-alpha Save, fixed run/job binding, HTTPS witness, storage ceiling, unchanged-seed check, and exact cleanup.
- **Ledger installation boundary:** the trusted record template carries a deliberate all-zero Cyberbaser tooling placeholder and never falls back to a mutable ref. Replacing it with one reviewed commit and installing both workflows in the external vault requires separate explicit authorization.
- **Owner-alpha isolation:** privileged editor/API and unprivileged Quartz reader run on separate origins of one owner-chosen private numeric IPv4 address (loopback default; RFC 1918 and RFC 6598 accepted; transport-neutral, no overlay-vendor coupling). Per-device bootstrap sessions, durable-before-acknowledgement Saves, fail-closed restart recovery, and an immutable pinned renderer commit.
- **WP2 deployment:** one local-only Linux/amd64 OCI image, explicit rootless `0:0` and rootful exact-UID/GID Docker Engine profiles, mandatory Linux host networking, no `ports:`, `/vault` as the only writable host bind, read-only config staged into private tmpfs, profile-bound state volume, operator-supplied HTTPS credential socket, offline Quartz seed, disabled engine logging, attached `b` bootstrap re-arm, and readiness after recovery. Mechanical acceptance passed on a real rootless daemon plus numeric nonzero identity fixtures; actual rootful-daemon, physical-device, external-live, registry, and service-install evidence remains pending.
- Renderers and hosts are swappable commodity spokes; never couple the hub to one SSG or forge. GitHub Pages is current, Cloudflare stays edge-only, and self-hosted Forgejo remains preferred for identity/hosting. WP3 phase one is complete within its controlled fixture evidence boundary and did not cut over authority, install a service, publish an image, or select production credentials. WP4's shared contract, Forgejo Lane A adapter, local queue, Lane B adapter/app, disabled Quartz form, and local-only sibling-service bundle are implemented and mechanically tested at their stated layers. The no-R-number amendment selects the v1 local queue and sibling service. Neither lane is offered; Lane B is unexposed and human-untested. Q09 remains open.
